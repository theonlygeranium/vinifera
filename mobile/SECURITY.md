# Native security boundary

Vinifera uses Capacitor 8 with the web application as the single UI source of
truth. Native capabilities are additive and remain unavailable on the
production web surface.

## Reviewed native dependencies

| Package | Version | License | Boundary |
| --- | --- | --- | --- |
| `@aparajita/capacitor-biometric-auth` | 10.0.0 | MIT | Uses the platform biometric prompt. A successful prompt only unlocks retrieval of a server-revocable refresh token; it is never authentication authority. |
| `@aparajita/capacitor-secure-storage` | 8.0.0 | MIT | Stores iOS data in the app-specific encrypted Keychain. Android data is encrypted with AES-GCM using a key generated by Android Keystore before storage in app-specific SharedPreferences. |
| `@capacitor/app` | 8.1.1 | MIT | Supplies app lifecycle, version identity, and allowlisted deep-link events. It does not authorize navigation on its own. |
| `@capacitor/barcode-scanner` | 3.1.0 | MIT | Uses the camera for fulfillment barcode scans. Images and video frames are not retained or uploaded. |
| `@capacitor/network` | 8.0.1 | MIT | Reports connectivity only; it does not read network identifiers or location. |
| `@capacitor/push-notifications` | 8.1.2 | MIT | Registers platform push tokens after member permission. Tokens are encrypted server-side and are never analytics identifiers. |
| `@capacitor/core`, `@capacitor/ios`, `@capacitor/android` | 8.4.2 | MIT | Native bridge and platform shells. No remote JavaScript loader is configured. |

The secure-storage plugin's web implementation uses unencrypted Web Storage.
Vinifera therefore hard-gates every storage call with
`Capacitor.isNativePlatform()`. It never stores access tokens, refresh tokens,
member data, or offline snapshots through that plugin on the web. A runtime
guard fails closed if secure storage is requested outside a native shell.

## Application identity and link trust

`mobile/app-identity.json` is the checked-in identity contract:

- bundle/package ID: `ai.edstratumlabs.vinifera`;
- version: `0.5.0` (`5`);
- only custom scheme: `vinifera.ai`;
- only universal-link host: `vinifera-live.edstratumlabs.ai`; and
- only external routes: `/portal`, `/portal/auth`, and `/app/fulfillment`.

The runtime rejects the separate `vinifera.edstratumlabs.ai` marketing host,
lookalike schemes, sibling subdomains, unknown hosts, and
routes outside that exact list. iOS AASA, Android App Links, native manifests,
the mobile authentication redirect, Capacitor configuration, and native
version fields are checked by `npm run qa:mobile:identity`. Changing any of
these values requires changing the identity contract and every verified
consumer together.

## Session policy

- Members still authenticate through a short-lived, single-use magic link.
- The native callback exchanges the one-time code for a Supabase access JWT
  and rolling opaque refresh token.
- Tokens are written only to native secure storage.
- Biometric or device-credential confirmation is required before a stored
  refresh token is read after cold start or foreground relock.
- Server logout and refresh-token rotation retain revocation authority.
- If secure storage, biometry, or the mobile auth API is unavailable, the app
  returns to magic-link sign-in. It does not fall back to localStorage.

## Offline policy

Only the member's minimized mobile bootstrap snapshot is cached, encrypted in
native secure storage. Offline mode is read-only: shipment and loyalty data may
be viewed, while address, payment, retention, and fulfillment mutations remain
disabled until the network reconnects. No offline mutation is silently queued.

## Platform permission and data inventory

### iOS

- Entitlements: associated domains and APNs only. Debug uses the development
  APNs entitlement; Release uses production.
- Usage descriptions: camera for barcode scanning and Face ID for local
  session unlock.
- No location, microphone, Contacts, Photos, Health, Bluetooth, or tracking
  entitlement is requested.
- `PrivacyInfo.xcprivacy` declares linked, non-tracking collection needed for
  app functionality: name, email, phone, physical address, internal user ID,
  push/device ID, purchase history, and product interaction.
- Payment card data is collected by Stripe's payment boundary, not Vinifera,
  and is not stored in the app.
- The app does not itself call an Apple required-reason API. The accessed API
  list therefore remains empty; dependency privacy manifests must be reviewed
  again whenever a native package changes.

### Android

- Permissions: Internet, camera, notifications, and biometric authentication.
- Backups and cleartext traffic are disabled.
- The non-exported `FileProvider` grants only `files/exports/` and
  `cache/exports/`; it cannot expose external storage or an entire app
  directory.
- No location, microphone, contacts, media-library, advertising-ID, or
  broad-storage permission is requested.
- APNs is never used for Android. Android delivery requires an activated FCM
  service account and `google-services.json` in the protected build
  environment.

## Push credential boundary

APNs and FCM are platform-specific delivery paths. iOS uses APNs with all of
`APNS_ENVIRONMENT`, `APNS_BUNDLE_ID`, `APNS_TEAM_ID`, `APNS_KEY_ID`, and
`APNS_PRIVATE_KEY`. `APNS_ENVIRONMENT=sandbox` selects Apple's sandbox host;
`production` selects the production host. Startup remains dormant when the
set is absent, while a partial set, an invalid environment, or a mismatch
between `APNS_BUNDLE_ID` and `MOBILE_IOS_BUNDLE_ID` fails activation.

Android uses FCM with `FCM_PROJECT_ID`, `FCM_CLIENT_EMAIL`, and
`FCM_PRIVATE_KEY`. Each transport is tested independently, but production
queue activation is deliberately joint: the scheduler claims no messages
until both complete provider sets are configured. This prevents leasing or
burning attempts for devices on a platform whose credentials are pending.

## Release hardening

- Android Release enables R8 code minification and resource shrinking.
  Capacitor/plugin consumer rules remain authoritative; app rules retain only
  runtime annotations, JavaScript bridge methods, and line numbers used for
  symbolicated crash reports.
- Debug builds remain unminified. A signed Release build must pass smoke tests
  for magic-link exchange, secure storage, push registration, biometric
  unlock, barcode scanning, and notification navigation before upload.
- The Gradle 8.14.3 distribution is pinned by SHA-256.
- Node is constrained to `>=22.12.0`; `.nvmrc` and CI select 22.22.0.
- App icons and splash screens are generated from the version-controlled
  Vinifera grape/vine artwork with `npm run generate:mobile:assets`. The iOS
  icon is emitted without an alpha channel.

## Update policy

The native bundle is immutable after store signing. On launch and foreground,
the app checks a server policy for minimum and latest store versions. It may
recommend or require a store update, but never downloads or executes arbitrary
remote JavaScript.
