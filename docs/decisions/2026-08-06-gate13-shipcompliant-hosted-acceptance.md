# ADR: Gate 13 ShipCompliant hosted acceptance evidence

- **Status:** Accepted
- **Date:** 2026-08-06
- **Decision owners:** EdStratum Labs

## Context

Vinifera's ShipCompliant adapter and append-only compliance ledger are
source-complete, but configuration readiness does not prove a real sandbox
contract, legal decision mapping, tenant isolation, fail-closed labeling, or
durable label recovery. Gate 13 must be proven before Gate 6 because the real
label path invokes ShipCompliant immediately before EasyPost.

ShipCompliant uses an OAuth request/response contract in this integration. It
does not provide a Vinifera webhook boundary to validate, so inventing webhook
evidence would create a false acceptance criterion.

## Decision

Add a dedicated `workflow_dispatch` controller that:

- runs only from an immutable commit that is still the canonical `main` head;
- uses the protected, main-branch-only `staging-acceptance-control`
  environment and a separate one-shot
  `STAGING_GATE13_ACCEPTANCE_ENABLED` switch, disabled by default;
- requires the deployed revision to equal the canonical `staging` head and
  requires exact operator confirmation;
- hashes and compares the stable sandbox account, license, origin,
  OAuth/check paths, contract version, Worker origin, and Supabase URL against
  a checked-in, fail-closed policy; the exact fixture-manifest byte hash is
  supplied separately through protected post-immutable environment state so
  its candidate revision cannot create a commit-SHA fixed point;
- calls the already-deployed Worker so provider credentials remain in the
  trusted runtime, while a service-role client reads only organization- and
  brand-scoped hosted evidence;
- compares the reviewed account, license, origin, contract, and endpoint-path
  hashes to hashes computed from the deployed Worker's actual bindings,
  including the normalized Supabase origin so Worker and database target
  identity cannot be reviewed independently;
- proves vendor compliant, non-compliant, unknown, timeout, and tax mappings;
- classifies only an actual request-deadline abort during either fetch or
  response-body streaming as timeout evidence; generic DNS, TLS, connection,
  authentication, malformed-body, and HTTP failures remain distinct;
- proves each non-compliant, unknown, and timeout label denial returns the
  matching ShipCompliant status and auditable decision identity without
  creating an EasyPost attempt;
- proves explicitly brand-scoped cross-tenant denial and reversible compliance-fingerprint
  invalidation, with exact one-row mutation and verified restoration to the
  original address plus the intentionally invalidated decision state;
- proves a completed EasyPost attempt is returned without another purchase;
- verifies append-only compliance and audit rows plus the exact analytics
  idempotency keys generated by the acceptance scenarios; and
- retains only a sanitized exact-revision artifact for 90 days with
  `completionClaimed: false`.

The recovery acceptance also corrects the service boundary so a
`label_created` shipment can reach the database's existing successful-attempt
recovery disposition even while purchase credentials or winery-origin contact
configuration are unavailable. Purchase-only configuration is loaded lazily
for charged shipments. The returned provider evidence is validated before any
analytics write, and acceptance verifies the reusable shipment plus succeeded
attempt are unchanged.

## Consequences

The controller remains inert until every stable policy hash, protected
per-run manifest hash, fixture, and one-shot switch is deliberately
provisioned. A passing artifact
is hosted acceptance evidence for Gate 13; the gate is recorded complete only
after an operator verifies the exact run and artifact against the runbook.
Cloudflare Access headers are attached only to the two exact, reviewed staging
origins: the Worker and the Access-protected Supabase ingress. The Supabase
transport rejects redirects before attaching the token, and neither transport
forwards it to ShipCompliant, EasyPost, or any other provider target.
Compliance and analytics evidence are matched by their exact response IDs and
full stable idempotency hashes without a run-start timestamp cutoff, allowing a
deterministic timeout decision to be verified safely on a retry.

Source code cannot create or infer the Sovos/ShipCompliant account, API
credentials, winery license, contract paths/version, vendor-authored scenario
addresses, dedicated charged fixtures, or a real completed EasyPost recovery
attempt. Those are explicit external prerequisites.

No ShipCompliant webhook is added. No production, live-billing, DNS, or
mobile-store control is changed.
